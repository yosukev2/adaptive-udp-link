# PR運用ルール

## 基本方針

- PR本文はIssue全体ではなく、そのPRの差分を説明する。
- Issue本文の全タスクをPRへ転記しない。
- 1つのIssueに複数のPRが作られる場合がある。
- 実機作業やCodex外作業が残る場合は、同一Issue内の残タスクとして明記する。

## スコープ

このPRで扱う範囲だけを書く。

## 変更内容

このPRで変更したファイルや動作だけを書く。

## 確認内容

- 実際に実行または確認した内容だけを書く。
- 未確認の内容を確認済みとして書かない。
- このPRで確認すべき内容が未確認なら、その状態を明記する。

## 残タスク

- このPR後、同一Issue内でまだ必要な作業だけを書く。
- 残タスクがなければ「なし」と書く。
- 別Issueが担当する作業は原則として書かない。

## Issue DoD対応

- このPRで満たしたDoDだけをチェックする。
- 後続PRや実機作業で満たすDoDはチェックしない。

## 関連Issue

- このPRだけでIssueを完了できる場合は `Closes #xxx` を使う。
- 同一Issueの途中PRでは `Refs #xxx` を使う。
