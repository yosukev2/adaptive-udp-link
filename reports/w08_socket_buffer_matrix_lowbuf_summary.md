# W08 socket buffer matrix summary

## 結論

- 54 runs すべて `run_validity=ok`。
- `rate_hz=10000 / 14000 / 18000`、requested rcvbuf `100000` 以下の範囲で、actual buffer 差と latency/drop の関係を見る。
- 前回は `262144` 以上が actual `425984` に丸められたため、今回は `8192..98304` の低 requested 領域に絞った。
- `missing_delta_total`、p95/p99/max latency、actual rcvbuf を組み合わせて効果を見る。
- CPU 指標は logs がある場合に別途 `rx_1sec.csv` / `tx.log` から集計する。

## preliminary observations

- `getsockopt()` actual は requested の約2倍で段階的に変化した。今回の低 requested 範囲では、前回のような `425984` への一律丸めは起きていない。
- `rcvbuf_requested=8192` では全 rate で少量の `missing_delta_total` が出た。`16384` 以上では今回の範囲では missing は出ていない。
- latency の p95/p99 は大きくは崩れていないが、max latency は条件によって外れ値がある。CPU 指標は logs がある場合に別途集計する。
