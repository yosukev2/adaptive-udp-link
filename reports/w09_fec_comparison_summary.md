# W09 random_drop + XOR FEC比較 summary

## 実験条件

- 比較対象: FEC OFF と FEC ON(xor)
- random drop target: datagram
- drop_rate: 0.10
- trials: FEC OFF 10回 / FEC ON 10回
- 同じrate_hz内では、同じtrial番号でFEC OFF/ONに同じdrop_seedを使用
- duration: tx 30 sec / rx 32 sec
- loopback: 127.0.0.1
- payload_len: 48
- CPU affinity: RX core 2 / TX core 3
- rate_hz: 1200 と 120000

## 結論

- rate_hz=1,200: FEC ON(xor) は effective_missing_total を OFF 36,312 から ON 9,756 に減らした。削減率は 73.1328%。
- rate_hz=1,200: 結果的に使えるdatagram数は OFF 107,904、ON 116,757。差分は ON-OFF = +8,853 datagrams。
- rate_hz=120,000: FEC ON(xor) は effective_missing_total を OFF 3,602,061 から ON 976,164 に減らした。削減率は 72.8998%。
- rate_hz=120,000: 結果的に使えるdatagram数は OFF 10,799,302、ON 11,674,601。差分は ON-OFF = +875,299 datagrams。
- どちらのrate_hzでも raw_missing_total はOFF/ONでほぼ同等で、差分はFEC回復の効果として解釈できる。
- FEC ONではp99 latencyが上がる。XOR k=4,r=1ではparity到着後に欠落datagramを復元するため、回復分は遅延を持つ。
- FEC ONでもmissingは残る。1 block内で複数data datagramが欠ける、またはparity datagramが欠ける場合は回復できない。
